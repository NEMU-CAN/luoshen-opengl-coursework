# 四人协作

先共同验证main可以编译、贴图正常，再各开短分支。一项完整小改动对应一个PR，检查后合并，避免直接覆盖别人代码。

| 分工 | 范围 | 交付 |
|---|---|---|
| 美术与场景 | 布局、相机、人物朝向与比例 | 程序实际截图与布局参数 |
| 光照与材质 | graphics_support.h、shadow_map.h | 光照、纹理、阴影及参数说明 |
| 动画 | scene_motion.h及运动逻辑 | 统一时间的路径、暂停和重置 |
| 工程整合 | 构建、加载、交互、性能、发布 | 所有人能运行的main分支 |

main.cpp的交叉修改由整合者处理。人物已经定型，没有明确反馈不再改脸型和头发。

## 日常流程

1. `git switch main`，`git pull`，再 `git switch -c feature/简短英文名称`。
2. 修改自己模块，运行 `./scripts/build.ps1` 和 `./scripts/check.ps1`。
3. 影响画面的改动必须实际运行，PR附同角度截图与操作方法。
4. 推送分支并创建PR，由一位组员检查后合并。

不要提交bin、build、VS缓存、便携Blender、历史ZIP、录屏、密钥及学号等无关信息。

## 人物编辑

根目录assets中两个current目录保存原生工程；场景工程assets/luoshen-characters保存运行文件。修改后必须同时提交BLEND、重新导出的OBJ/MTL和必要贴图，并在程序里验证。BLEND不能逐行合并，同一人物一次只交给一个人编辑。

Y轴向上，沿用当前导出轴和缩放，模型位置以归一化包围盒底部为基准。

公开仓库可以浏览与提PR；直接推送须由所有者在Settings → Collaborators邀请。尚未提供组员GitHub用户名，因此不自动邀请任何账号。
