# 《洛水别绪》环境动态实现与验收报告

## 1. 任务概述

本次工作对应《协作说明.md》中的“环境动态”职责，目标是在不修改人物模型、人物路线和主场景布局的前提下，为画面增加水面花瓣、桃树飘落花瓣、动态水面和涟漪，并保证效果不会遮挡人物或破坏中央叙事留白。

本次最终完成了以下内容：

- 48 片水面漂移花瓣，其中 34 片沿左岸分布，14 片稀疏分布在开阔水面。
- 14 片桃树飘落花瓣，具有下落、横向摆动、偏航和翻滚效果。
- 水面波纹、波光和洛神脚边涟漪接入统一动画时间。
- 花瓣自动避让岸线、洛神、小舟和主镜头中央留白。
- 空格可以同时暂停水面与花瓣动态，R 可以重置时间并复现初始状态。
- 新增独立环境动态演示模式，便于脱离人物单独验收环境效果。
- 新增自动化测试，检查花瓣确定性、动态性、岸线约束和留白约束。

## 3. 环境动态模块实现

### 3.1 统一的花瓣姿态数据

`environment_effects.h` 中新增了 `PetalPose`，统一保存单片花瓣的状态：

- `position`：世界坐标位置。
- `yaw`：绕 Y 轴的旋转角度。
- `scale`：模型缩放。
- `tilt`：绕 X、Z 轴的倾斜，用于表现翻飞。

花瓣姿态由当前 `animationTime` 直接计算，而不是逐帧累加位置。因此暂停时画面会稳定停住，重置后同一时间点总能得到同一结果，不会因帧率不同产生漂移。

### 3.2 水面花瓣

水面花瓣数量由 `waterPetalCount=48` 控制。每片花瓣使用固定种子生成基础位置，再叠加低频正弦运动：

```text
x(t) = x0 + 0.10 sin(0.13t + seed)
z(t) = z0 + 0.18 sin(0.10t + 0.43seed)
y(t) = 0.014 + 0.003 sin(0.72t + seed)
```

这种运动幅度较小，表现水流推动下的缓慢漂移和轻微起伏，不会产生快速抖动。花瓣旋转速度也由固定种子控制，使不同花瓣不会同步旋转。

左岸花瓣根据实际岸线函数生成，形成近岸较密、河心较疏的分布。右侧开阔水面只放置少量花瓣，避免画面平均铺满。

### 3.3 桃树飘落花瓣

空中花瓣数量由 `fallingPetalCount=14` 控制。每片花瓣具有 7.5 至 11 秒的独立循环周期，并通过固定相位错开开始时间。

花瓣从桃树冠附近向下运动，同时叠加：

- 水平方向缓慢漂移。
- 正弦形式的左右摆动。
- 连续偏航旋转。
- X、Z 方向翻滚。

所有落花都围绕桃树位置计算，不会扩散到整幅画面或穿过主要人物区域。

### 3.4 岸线、人物与留白避让

水面花瓣绘制前会执行 `visibleWaterPetal(...)` 检查：

- 与实际岸线保持至少 `0.32` 个世界单位的水面距离。
- 与洛神保持至少 `0.78` 的水平距离。
- 与小舟保持至少 `1.05` 的水平距离。
- 不进入中央叙事留白椭圆。

中央留白椭圆中心为 `(-0.35, -4.4)`，X/Z 半轴分别为 `1.25` 和 `3.15`。判定公式为：

```text
((x + 0.35) / 1.25)^2 + ((z + 4.4) / 3.15)^2 < 1
```

椭圆内部不绘制水面花瓣，从而保留曹植、洛神和小舟之间的视觉通道。

### 3.5 水面波光与涟漪

`graphics_support.h` 原本已经包含动态水面法线、波光和洛神脚边涟漪公式，但主程序始终向 `sceneTime` 传入 `0`，所以水面实际处于静止状态。

本次没有覆盖共享着色器，而是在 `main.cpp` 中将 `sceneTime` 接到统一的 `animationTime`。因此以下原有效果开始随时间运行：

- 两组不同方向和速度的水面波形。
- 细窄水面亮纹。
- 暖色闪光带。
- 洛神脚边衰减的动态同心涟漪。
- 水中倒影的轻微横向扰动。

## 4. 主程序接入

### 4.1 统一动画时间

`main.cpp` 新增：

```cpp
bool animationPlaying=true;
double animationTime=0.0;
```

每帧只在 `animationPlaying` 为真时累加 `animationTime`。环境模块不创建第二个计时器，满足项目统一接口约定。

### 4.2 暂停与重置

- 按空格切换 `animationPlaying`，水面、涟漪和所有花瓣同时暂停或继续。
- 按 R 将 `animationTime` 设为 `0`、恢复播放并重置主视角。

程序启动自检也增加了暂停与重置检查。如果按键回调没有正确改变状态，程序会报告错误。

### 4.3 模型倾斜支持

原有 `drawModel(...)` 只支持绕 Y 轴旋转。本次在保持旧调用兼容的基础上增加了可选 `tilt` 参数，用于落花翻滚。已有场景模型不传该参数时默认值为零，因此原有摆放不会变化。

### 4.4 绘制位置

环境效果在水面、地形和主要场景物体绘制完成后调用：

```cpp
environment_effects::drawWaterPetals(...);
environment_effects::drawFallingPetals(...);
```

调用参数包含共享时间、洛神位置、小舟位置、桃树位置、观察矩阵和三种已有花瓣模型。模块不修改人物位置、相机或布局数据。

## 5. 在哪里查看

### 5.1 查看完整场景

进入 `场景工程_美术重制` 目录，双击：

```text
打开场景.cmd
```

完整场景中可以同时观察人物、花瓣、水波和涟漪。推荐先使用主视角，再按 `2` 查看全景。

### 5.2 单独查看环境动态

双击：

```text
场景工程_美术重制/演示环境动态.cmd
```

该模式等价于运行：

```powershell
场景工程_美术重制\bin\LuoshenScene.exe --environment-demo
```

独立演示模式会隐藏曹植和洛神，并切换到环境观察镜头，但保留水面、岸线、桃树、小舟、漂浮花瓣和落花。这样可以直接检查环境模块，不受人物模型遮挡。

### 5.3 操作方法

| 操作 | 效果 |
|---|---|
| 空格 | 暂停或继续全部环境动态 |
| R | 将动画时间重置为 0 并继续播放 |
| 左键拖动 | 环绕观察 |
| 右键拖动 | 平移观察中心 |

### 5.4 查看源代码

环境算法集中在：

```text
场景工程_美术重制/environment_effects.h
```

建议按以下顺序阅读：

1. `PetalPose`：花瓣姿态数据。
2. `waterPetalPose(...)`：水面花瓣运动。
3. `inCentralClearance(...)`：中央椭圆留白。
4. `visibleWaterPetal(...)`：岸线、人物和小舟避让。
5. `fallingPetalPose(...)`：桃树落花运动。
6. `drawWaterPetals(...)` 和 `drawFallingPetals(...)`：实际绘制入口。

主程序的时间、按键和绘制接入位于：

```text

```

## 7. 自动化测试内容

`mesh_tests.cpp` 新增的环境测试覆盖：

- 相同索引和相同时间得到完全相同的位置，验证可复现性。
- 时间从 0 变化到 2 秒后位置发生变化，验证环境确实读取共享时间。
- 可见水面花瓣不会越过岸线。
- 可见水面花瓣不会进入中央叙事留白。
- 避让过滤后仍保留足够花瓣，防止约束过严导致效果消失。
- 所有落花保持在桃树附近，并处于规定的高度范围。

## 9. 协作与合并说明

本次改动遵守环境模块文件边界：核心逻辑集中在 `environment_effects.h`。`main.cpp` 中只加入必要的统一时间、控制、演示模式和绘制接入。没有修改人物模型、人物路线和场景布局，也没有覆盖光照负责人维护的水面片元着色器。

后续合并时如果主程序已经由动画负责人加入新的全局 `animationTime`，应保留唯一的共享时钟，将本报告中的环境绘制调用改接到该时钟，避免同时存在两个时间变量。环境模块自身不需要调整。

## 10. 结论

环境动态模块已经满足本轮要求：水面花瓣数量克制、运动连续，桃树落花具有可见的飘落与翻飞，水面波光和涟漪由统一时间驱动；效果能够暂停、重置和独立演示，并通过自动测试与实际 OpenGL 渲染检查。主镜头中人物和中央叙事留白保持清晰，短时运行未出现明显性能下降。
